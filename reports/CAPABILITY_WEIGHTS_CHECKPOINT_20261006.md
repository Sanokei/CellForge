## The current research gap

The project goal is literal LLM-written tensor founders and mutations, competing
under equal charged budgets, with inheritance/crossover and reusable capability.
Direct answers do not create such genomes. More independent solved grids would
strengthen a solver baseline without demonstrating that loop.

There is one concrete representation diagnosis: `assoc_induct` maps every instance
of the same input color to the same output color. Task 1a07d186 requires different
outputs at equal-colored input positions. No weight mutation can break that
invariant; repeating that template/task pairing is not useful. The spatial
composition escaped that particular limitation but has not demonstrated an ARC
development gain. See `NATIVE_AGENT_V2_RESULT_20261006.md` for the training-only
proof, rather than attributing every null result to model weakness.

The proposed seven-value frequency-packing extension was not implemented. Its
counting/sorting/placement logic would live in host code, and its coarse control
space has substantial random success probability. It would be a transparent
host-algorithm baseline, not evidence that neural weights learned frequency
packing. Likewise, identity router coefficients cannot be presented as learning
the already supplied demonstration-error routing mechanism.

No result here demonstrates a single learned model across ARC-1/2/3, a capable
chatbot, or AGI. ARC-3 runtime/action experiments are owned separately; this
checkpoint does not invent or restate their current live outcomes.

## Gate for the next weights experiment

Before any new author tranche, select one falsifiable hypothesis about reusable
weight behavior and freeze its scope. The useful target is a **single fixed cell
or typed bank whose literal weights improve shared behavior after training-only
counterexamples**, not a new task-specific host function for each solved grid.
Prefer existing expressive components; if none can express the proposed behavior,
document that boundary before requesting more numeric guesses.

The next proposal should make the following concrete and reviewable:

1. Identify what behavior is determined by the authored tensors and what the host
   already implements. Keep executable structure fixed during a weights-only
   comparison; label structure invention and direct programs separately.
2. State the founder/mutation or inheritance claim being tested, a finite call
   and position budget, and a stop condition. Do not claim crossover without
   saved lineage and an appropriate comparison.
3. Select only from training/development evidence. The current direct panels are
   now exposed development data. Freeze any new report evaluation before access;
   excluded evaluation/private access and closed campaigns remain protected.
4. Compare with the simplest capable host reference, zero tensors and valid
   matched-random proposals/edits under the same allowed vocabulary and charged
   positions. Count invalid submissions and functional duplicates. Crashing
   controls cannot establish meaningful weight dependence.
5. Recompute the claimed gain from saved source and tensors in an independent
   process, with query outputs stripped, raw provenance and cancellation/STOP
   behavior intact. A successful undersized probe still does not satisfy the
   broader population standard.

This is a decision gate, not a newly authorized run or a request to build another
framework. The parent should choose the concrete shared-weight hypothesis and
bounded milestone after reviewing these results. No larger call allocation is
implied by the owner's general aspiration.
