# Offline lossless NCA encoding audit

## Decision

There is a demonstrable opportunity to reduce redundant transport text without
changing any numerical degree of freedom. It is **not** evidence that text size
caused either timeout, that a new encoding would finish faster, or that the model
can author useful tensors. Both timed-out studies remain closed and incomplete.
No model call, reservation, runtime prediction, fitting or new scientific tensor
was performed. This report does not authorize a new study or output format.

## Exact saved-data measurement

Input is the already accepted identity response from
`runs/weights-nca-author-tranche-20261008/attempts/01/RAW_RESPONSE.bin`, whose
SHA256 is `ea8591a8811eed9a65416cc98edee40f67c9dec7b0c8ade2a4165c42f74e9335`.
It is byte-identical to the later comparison-A response. The audit binds the
original founder packet and response schema by their recorded hashes.

| Item | Existing | Illustrative flat literal envelope |
|---|---:|---:|
| Response bytes, same saved numerical values | 4,597 | 3,108 |
| JSON schema bytes | 15,494 | 368 |
| Required numeric scalar positions | 1,488 | 1,488 |
| Reconstructed arrays | 96 | 96 |

The measured response reduction is 1,489 bytes (approximately 32.4%). The example
schema is approximately 97.6% smaller in bytes, but is **not validated against the
backend's supported JSON-schema dialect**. Schema syntax here is an illustrative
local design, not an endpoint-accepted contract.

The frozen tensor layout remains essential. Its existing packet representation
is 4,841 bytes and is not removed or counted as a saving. It specifies names,
shapes and position counts. The illustrative envelope includes a layout SHA256
so a changed shape/order cannot silently reinterpret the vector. A shorter
3,025-byte vector envelope without that hash was examined initially; the table
uses the safer layout-bound envelope instead.

The vector retains all 1,488 literals, including zero and inactive/redundant
positions. It uses no defaults, sparsity convention, generator program, symbolic
formula, host-selected weights or compressed numerical codebook. A trusted fixed
decoder validates exact length/vocabulary/hash, then reshapes values into the
96 predetermined arrays in lexicographic-name, C/row-major order. Validation and
reconstruction are linear passes over the positions; normal JSON/container
allocation overhead remains. No runtime code is generated by an author.

The roundtrip reconstructed every value and shape exactly. Canonically serializing
the reconstructed original envelope reproduces the exact 4,597 original bytes.
That is a serialization fact about already saved data, not a new candidate or a
replay of the NCA. No proposed candidate file was saved or supplied to an intake.

## What the captures establish, and what they do not

Existing capture receipts show:

| Invocation | Packet bytes | Wall seconds | Completion |
|---|---:|---:|---|
| Original founder | 16,752 | 82.256 | Valid identity response |
| Mutation | 27,507 | 120.056 | Timeout; no final or usage |
| Comparison A | 16,752 | 81.609 | Same exact identity response |
| Comparison B | 17,203 | 120.118 | Timeout; no final or usage |

All used the same 15,494-byte response schema. B's objective clarification adds
451 packet bytes (2.69%); mutation adds 10,755 (64.2%). Their common timeout
outcome does not isolate a size effect. Original packet plus schema totals
32,246 bytes; B totals 32,697; mutation totals 43,001. These arithmetic byte sums
are **not** the actual backend request size or input-token count.

Completed native usage counters were input 24,742 for both; output 3,892/3,920;
reasoning-output 73/101; cached and cache-write input zero. Counters are preserved
separately, without asserting additive relationships. Identical final bytes with
different counters do not identify any particular internal processing mechanism.

The timeout captures contain only `thread.started` and `turn.started` (101 raw
stdout bytes), no unterminated stdout tail, and no final/usage event. The wrapper's
120-second timer begins before process creation: it includes startup, service
latency and generation, whose separate durations are unobserved. No per-event
arrival times or token-stream timing were recorded. Missing completion is not
zero model computation, zero cost, a failed tensor prediction, or proof that a
longer timeout would succeed. Exit -15 and recorded wall timeout describe the
client-side termination, not verified cancellation of backend computation.

The captured configuration requests `gpt-6.1-sol` with reasoning effort `low`.
That selector is not an observed fixed compute allowance. The reviewed argv does
not explicitly set a maximum output-token count; effective backend defaults
remain unknown. Peak owned RSS was 139,640–141,524 KiB, with wall-time rather than
RSS rejection. Neither this nor unchanged coarse quota percentages explains why
the two invocations failed to complete. No cost is inferred from absent usage.

`tiktoken` is not installed in this workspace and the backend tokenizer has not
been verified. No tokenizer was downloaded; this audit supplies actual byte
counts, not token estimates or forecast latency savings.

## Bounded next step and stopping rule

The useful authorized offline control is complete: exact roundtrip, schema/layout
burden accounting and rejection fixtures. Stop here rather than repeatedly
renaming timed-out studies or extending limits after observing failures.

If the owner later authorizes a prospective representation experiment, it must
have a distinct frozen question (completion/serialization versus numerical
quality), a reviewed accepted schema/decoder, unchanged numerical vocabulary and
all-position charges, finite call and time budgets, and a predeclared incomplete
outcome. Changing representation cannot repair or complete comparison B. Preserve
both historical timeouts and the entire call/cost history. No automatic call,
healthcheck, runtime scoring or publication follows from this report.
