# CellForge continuous shared spatial exploration, 2026-10-11

The owner requests durable sequential CellForge research on existing compute.
This is a new development study. It does not restart closed legacy campaigns,
change their source, or remove their STOP files.

The October 2 recovery checkpoint found that per-action aggregate pixel-change
memory could not ground spatial clicks or delayed consequences. This study
tests a narrower new hypothesis: generic rare-region/boundary exploration
combined with action-conditioned stagnation recovery improves useful levels.
It uses the SAME source and literal tensors on ar25, lp85, sc25. Those public
games were already exposed and are development evidence only. No game IDs,
colour identities, goals, solutions, or withheld validation material reach policy.

Three explicit hypotheses compare rare-region and boundary click features,
and stronger stagnation recovery. Each has 16 literal parameters supplied by
the assistant in this authorized conversation, not by a new server maker call.
No complete platform-context hash is available; no remote provider provenance
is invented. They are a recorded numerical design study, not a population
evolution or mutation result. The generic new runtime is infrastructure.
Its version never changes historical evaluation/runtime/templates.

Freeze nine experiments: three hypotheses x environment seeds 0, 2, 3.
Order all three hypotheses at seed 0, then seed 2, then seed 3.
Per experiment: 1500 actions per game and arm; authored, matched random,
zero, spatial-off, action-off, blind. Random gets the same 16 charged positions.
Each hypothesis has three independent random draws across the three seeds.
Fixed ablations are not extra matched evolutionary proposals.
All results, crashes and terminal receipts are retained, not just a champion.
No outcomes select/tune a candidate; no automatic promotion or new generation.
The study ends after nine distinct fingerprints and pauses for an audit/new
hypothesis. A failed experiment is never blindly retried with a new timestamp.

Scientific interpretation: levels are the primary capability measure;
no-op/distinct-frame counts diagnose mechanism only. Compare the SAME hypothesis
across games/seeds with its matched random, zero and blind controls.
This study cannot establish novel-game transfer, full ONE_STANDARD qualification,
a learned-router benefit, crossover advantage, or general intelligence.
Each run truthfully writes qualified=false. Required historical test failures
remain visible; neither floors nor tests are weakened.

Existing ARC-3 OFFLINE adapter and AST/network/rlimit policy sandbox are copied
byte-for-byte from the existing server. The parent systemd cgroup additionally
blocks networking and private validation paths. Recorded first-400 action traces,
source hashes, development-file hashes and seeds permit deterministic replay;
final frames are hashed, not published. Offline recordings are disposable scratch.

Runtime limits apply to the complete job tree: CPUQuota=100%, CPUAffinity=0,
numeric library threads=1, MemoryMax=1GiB, MemorySwapMax=0, 600-second wall limit,
TasksMax=64, KillMode=control-group, OOMPolicy=kill. Disk free must exceed 5GiB;
run artifacts/scratch are capped at 64MiB and the study at 256MiB.
Logs rotate at 1MiB; worker output is limited to bounded atomic artifacts.
There is one durable queue and one fixed job unit, protected by global flock.
After failure: 30/60/120-second backoff; three consecutive failures block.
STOP and per-fingerprint cancellation override continuation. Terminal receipts
are atomic and fsynced; cgroup emptiness is required before every next launch.

Zero remote maker calls and zero paid API calls are allowed. The legacy
maker.py reads session rollouts, so it is deliberately not invoked. A future
writer queue must use supported fresh account quota RPC, preserve the existing
85% ceiling and tranche gates, and receive a separately frozen scientific plan.
Neither credentials nor network/security configuration is changed.
